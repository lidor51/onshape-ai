## First Real Smoke

Admission plus the delivered prepared plate requires a **real UI attempt**, not
silent skipping. Until those inputs exist, do not run CAD, login or create a doc.

1. Start persistent pilot counters before any browser observation/action. Reuse a
   shared page on the parent's verified exact HTTPS Onshape stack. Reject unexpected
   origins and redirects. Record only nonsecret visible evidence, never auth pages.
2. Use the supplied trial-owned public synthetic destination or create the arm's
   single new explicitly public document through ordinary UI after checking the
   ledger. Copy/import destinations count. Record visible ownership, URL and
   visibility. This document must also serve later checkpoints; no second smoke doc.
3. Submit the parent's prepared plate/source using visible editors, upload controls
   and ordinary feature dialogs. Do not author replacement CAD or borrow an API
   result. Confirm solid/feature health and the packet's dimensions in visible UI.
4. Open the **source parameter UI**; record a named parameter, units and original
   value. Apply the packet's bounded revision, regenerate and verify the expected
   change. Record original/revised values and visible source/feature health.
5. Navigate away and resume the same trial document once. Reopen the parameter
   dialog; verify persisted value and healthy unsuppressed parts. Retain sanitized
   UI screenshots and source/packet hashes. A plate PASS does not prove assembly
   mates, human usability or the subsystem. No full model before the comparison
   packet is ready and smoke is PASS.

## Assembly Checkpoints

Checkpoint 1 is same-packet baseline: actual named native instances and native
fixed/rotating mates, joint limits and stow/deploy/intermediate positions. Check
suppression, missing references and errors, not just a rendered pose. Record COTS
identities and interfaces, distinguishing real manufacturer geometry from proxies.
Classify clearances as analytic, sampled or unverified. Save original UI-downloaded
baseline exports and hashes without relabeling local files as Onshape exports.

Checkpoint 2 is the bounded source-parameter UI revision followed by resume:
reopen the same document and assembly, confirm retained instance/mate identities,
unsuppressed parts **and assembly mates**, native motion/limits and no regeneration
errors. Record editable control names/units/values, health before/after and original
revision exports. STEP placement or static parts do not satisfy native assembly
behavior. API edit simulation does not satisfy UI editing; automated UI editing
does not establish observed human usability.

## Hard Bounds And Evidence

- Pilot: at most 60 tool invocations, 60 individual UI actions, or 15 active minutes,
  whichever is reached first. Count subactions in scripts, not just wrapper calls.
- At most two assembly checkpoints, each with the same limits, and one repair
  checkpoint across the entire arm with those limits. No reset after resume.
- Zero direct API calls, Onshape MCP, browser request clients, injected fetch/XHR,
  hidden application methods, cookie/localStorage inspection, credential reads,
  auth HAR capture, session replay or OAuth proxy. No new paid service.
- No blind retries, repeated refreshes, public-CAD crawl, source-corpus rebuild or
  research ranking. No existing robot changes, sharing changes or document deletion.
- Stop at policy/access restriction, unexpected authentication, quota, unsafe
  origin, unknown mutation outcome, wrong packet or exhausted bound. Record the
  concrete condition; do not convert a gate into a failed CAD score. Preserve the
  persistent ledger and charge uncertain actions before attempting anything else.
- For every admitted action record phase, monotonic elapsed/active time, individual
  action count, observed result, intervention/recovery and sanitized artifact path.
  Human login time is an intervention, not hidden from wall time. Never store
  cookies, headers, storage dumps, auth screenshots or secret-bearing error text.
- Use [paired results](paired-results.json) and the [schema](result.schema.json).
  Nonexecuted metrics stay null. Count known no-action accounting separately as
  zero. API placeholders are not sibling results; the parent integrates its own
  evidence. Shared preparation timing remains separate from arm execution timing.

Physical acquisition, endurance and manufacturing release remain UNVERIFIED
without actual physical tests and review. No relative speed, rank or statistical
success claim is available from a blocked browser arm.
